# 午夜超商小偷 — 灰盒驗證原型

單一 HTML 檔的第一人稱原型，用來在投入 Cocos Creator 之前先回答一個問題：

> **明明已經可以乾淨脫身，你還會不會回頭去拿最貴的那件？**

如果這個抉擇在灰盒裡就成立，那它在完整美術下只會更強；如果不成立，
再好的美術也救不回來。所以這支原型刻意不做美術，只做決策。

---

## 怎麼玩

- **線上版（建議）**：https://pwart475.github.io/midnight-store-thief/
- **本機**：雙擊 `index.html`
  - 注意 `file://` 不是安全來源，瀏覽器會拒絕 `unadjustedMovement`，
    滑鼠會帶著作業系統的指標加速（慢推幾乎不動、快甩又過頭）。
    要正常手感就跑 `serve.bat`，它會用 `http://localhost` 開。

### 操作

| | 電腦 | 手機（橫向） |
|---|---|---|
| 移動 | W A S D | 左下任一點按住即是搖桿（圈平常隱形，碰到才浮出來） |
| 轉頭 | 滑鼠（點畫面鎖定游標） | 右半邊拖曳 |
| 衝刺 / 潛行 | Shift / C | 搖桿推到外圈 = 衝刺 |
| 撿東西 | E | 右下「拿」 |
| 開火 | **滑鼠左鍵**（打手上那一把） | **左側中間「射」** |
| 換手 | Q 電擊槍 / G 長槍 | 右側「電」/「雷」 |
| 跳 | 空白（需購買） | 右下「跳」 |
| 縮小劑 | R（需購買） | 右下「縮」 |
| 全螢幕 / 調參 | F / T | 左上兩顆 |

手上同時只拿一把槍。**右邊選，主手射**——手機上右手在轉鏡頭，
所以開火鍵在左邊；電腦上手已經在滑鼠上，所以開火是左鍵。

## 檔案

| 檔案 | 用途 |
|---|---|
| `night_shift_proto.html` | **遊戲本體**。約 9,300 行，所有東西都在這一支裡面 |
| `index.html` | 啟動器。用 iframe 包住遊戲，負責 `allow="pointer-lock"` 與行動裝置的縮放鎖定 |
| `tex/*.png` | 商品貼圖（47 張）＋ 店長海報 ＋ 三張促銷海報 |
| `push.bat` | 找出 Claude 最新寫出的版本，複製到這裡並推上 GitHub Pages |
| `serve.bat` | 開一個本機伺服器，讓滑鼠原始輸入能用 |

`night_shift_proto.html` 不依賴任何建置步驟。Three.js r128 走 cdnjs，
字型走 Google Fonts，其餘全部內嵌。貼圖是唯一的外部檔案，
而且找不到的話會自動退回程序化的積木，不會開天窗。

### 推版

雙擊 `push.bat`。它會：

1. 掃過 Claude 的工作階段資料夾，找**最新**的 `night_shift_proto.html` 複製過來
   （不是只在本地沒有檔案時才抓——那個舊行為會讓你一直推同一份舊版還回報成功）
2. 連同 `index.html`、`tex\*.png` 一起 commit 並 push
3. GitHub Pages 大約 30～60 秒後生效

**版本對不對，只有一個地方不會騙你**：標題畫面上方那行 `灰盒驗證原型 V14.xx`。
遇到「改了沒效」的時候先看那一行。

## 調參面板（T）

七十幾個旋鈕，改了立刻生效，不用重開。搜尋框比分類好用——
中文標籤和英文鍵名都比對，打「亮度」或「light」都找得到。

面板最下面還有兩區：

- **效能**：開啟後畫面上方出現 FPS / 中位 / p95 / 最差幀、draw call、
  三角數、GPU 物件數、heap。「複製效能數據」把快照複製成 JSON。
  **看 p95 和最差，不要看平均**——平均 60 但每兩秒掉到 20 的遊戲，
  玩起來比穩定 40 糟得多，而平均值會把那件事藏起來。
- **作弊（測試用）**：一鍵拿到長槍／電擊槍／$5000。
  走的是跟正規取得完全一樣的欄位，所以測出來的手感就是玩家會遇到的。

`dev-copy`（複製全部數據）會把 CFG、STATS、現金、裝備、這一局的佈局代號
和事件記錄全部輸出成 JSON——調完參數之後用這個回報。

## 機器人跑分

Console 裡有 `NSSIM`：

```js
NSSIM.batch(6, 8)        // 四種性格各 6 條命、每條最多 8 關
NSSIM.personas           // 貪心仔 / 穩健派 / 探索者 / 恐慌型
NSSIM.snapshot()         // 現在場上有什麼
NSSIM.setCfg({...})      // 暫時改參數跑一輪
```

**但要知道它的極限**：這個機器人逃跑的能力比人類差很多。
這個專案已經兩次拿它的數字去改設計、兩次都錯：

- 一次把非賣品價值從 450 調到 250，理由是「機器人帶著它逃不掉」——
  而真人 8 次全部成功。
- 一次因為「探索者只有 10% 存活率」去改店員 AI——
  真正的原因是機器人會在被追的時候朝 14 公尺外的立櫃跑過去，
  改成 4.5 公尺之後同一個性格跳到 27%，遊戲一個字都沒改。

**它適合測「會不會卡住、走不走得到」，不適合測「難不難」。**
難度只能靠真人跑，而且要看 `exportData` 的真實紀錄。

## 目前的狀態（v14.37）

### 已經成立的
- 核心迴圈：偷 → 解鎖出口 → 要不要回頭拿非賣品 → 脫身 → 變賣 → 添裝備
- 非賣品價格每件各自抽（$250～$500 ×難度），所以「走過去看一眼」本身是個決定
- 店員：視線扇形、聽覺、巡邏／調查／搜尋／追擊／放棄，頭上有 ?／! 符號
- 電擊槍（三件部件組裝）、雷電長槍（辦公室 $5000、三槍解決一個、中一槍現形）
- 保險櫃兩段式（鑰匙→密碼）、拉霸機、立櫃躲藏、縮小劑、員工通道
- 第一人稱手持武器、電漿砲彈道、四軸評分、犯案紀錄

### 還沒驗證的
- **電腦版左鍵開火**：有玩家回報按了沒反應，但在推移轉向模式下實測是正常的。
  v14.32 之後三個靜默的 `return` 都會出聲，下次再遇到就能分辨是哪一種。
- 店員卡點的繞路修正（v14.33）寫完沒人實際玩過
- 電漿彈飛行中的樣子沒有人真的看過
- 觸控的開火鍵誤觸與滑開交棒只有靜態量測
- **效能完全沒量過**。這是目前最大的盲點，而目標平台是手機。

### 刻意不做的
- 現金、裝備、關卡進度**不存檔**。關掉瀏覽器就是新的一輪。
  只有犯案紀錄跨工作階段保留——那是唯一的成績。
- 多店員已經寫好但關著（`clerk2Shift` / `clerk3Shift` 設成 99）
- 連線：等單人夠完整再評估。方向是非對稱 1v1，透過 `getClerkIntent()` 抽象

## 這支檔案的讀法

程式碼裡的註解**不是在解釋程式在做什麼**，而是在記錄
「為什麼是這個數字」「上一版錯在哪」「這裡踩過什麼坑」。
要改任何一個常數之前，先讀它上面那段——多半已經有人試過另一個值了。

幾個反覆出現的坑，寫在這裡當索引：

- **three.js r128 的射線會打到 `visible:false` 的物件**。只設 visible 不夠，
  要一起設 `taken`。
- **`itemMat(color, emis)` 是用 `color|emis` 記憶化的共用材質**。
  絕對不能去改它回傳的材質，只能重新指派——不然全場同色的東西會一起變。
- **深度精度跟距離平方成反比**。16-bit 深度在 10 公尺外的最小可分辨間距
  大約是 19 公釐。地板、海報、牌子的間距都是照這個算的，
  排序原則是：地板 → 地面標記 → 燈光反射，由下而上各差 4～5 公分。
- **百分比定位在高度差兩倍的兩種螢幕上意思不一樣**。
  桌機 788 高、橫向手機 360 高——`top:46%` 在前者沒事，在後者會撞到提袋面板。
- **`cmd.exe` 的 `call :label` 會間歇性失敗**（它在執行中的檔案裡用位元組位移找標籤）。
  `push.bat` 裡所有複製都是攤平寫的，沒有標籤。
