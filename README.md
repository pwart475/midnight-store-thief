# 午夜超商小偷 — 灰盒驗證原型

單一 HTML 檔的 Three.js 第一人稱原型，用來在投入 Cocos 開發前先驗證核心玩法。

**線上版**：https://pwart475.github.io/midnight-store-thief/
**目前版本**：v3.6（標題頁左上角會顯示，那是唯一可信的版本來源）

---

## 這個原型要回答什麼

交接包（`night_shift_claude_handoff/CLAUDE.md`）的核心命題只有一句：

> 玩家本來已經可以安全撤離，但看見更高價值商品，決定多冒一次險。

所以整個原型只為一件事存在：**明明已經可以乾淨脫身，玩家還會不會回頭去拿最貴的那件。**

美術、音樂、內容量都不是重點。方塊就是商品，音效全部即時合成，沒有任何外部素材。

---

## 檔案結構

```
index.html               啟動器（必須從這支開）
night_shift_proto.html   遊戲本體，約 3000 行，單檔自足
manifest.webmanifest     PWA 設定，讓「加入主畫面」變成獨立全螢幕 App
icon.svg                 主畫面圖示
night_shift_claude_handoff/   原始交接文件（設計、技術棧、里程碼）
```

### 為什麼需要 `index.html`

它做兩件 `night_shift_proto.html` 自己做不到的事：

1. **`allow="pointer-lock"`** — 授權鎖定滑鼠。沒有它就只能用「推移轉向」，手感差很多。
2. **帶時間戳載入** — `?t=Date.now()`。手機瀏覽器的 HTML 快取極度頑固，改版後常常還在跑舊檔，看起來像「新版沒修好」，其實根本沒載到。這個坑吃掉過一整輪除錯時間。

**永遠從 `index.html` 開，不要直接開 `night_shift_proto.html`。**

---

## 部署

整包四個檔案丟到 GitHub Pages / itch.io / 任何靜態空間即可。`index.html` 就是這些平台預期的入口檔名。

Three.js（r128）與字型走公開 CDN，不需要打包，也沒有 build 步驟。

改版流程：覆蓋 `night_shift_proto.html` → commit → 等一分鐘。因為有時間戳，**測試者不需要清快取**。

### 手機（橫向）

左下**任一點**按住就是浮動搖桿，**推到外圈就是衝刺**（不需要額外按鍵）。右半邊拖曳轉頭。右下按鈕：拿、蹲，以及買了才會出現的跳／電／縮。

iOS 沒有 Fullscreen API（Apple 的限制，換任何瀏覽器都一樣）。要全螢幕請用 **Safari → 分享 → 加入主畫面**，從主畫面圖示啟動就沒有瀏覽器介面。Android 直接按全螢幕鍵即可。

## 核心系統

### 貪婪迴圈

拿 3 件 → 後門解鎖 → **這時跳出決策提示** → 走，或者去冷凍室拿那件非賣品 → 拿了就觸發停電、廣播、店員追逐 → 回後門結算 → 變賣 → 買裝備 → 再幹一次。

### 三個讓「多拿」自己帶著代價的機制

1. **負重**：提袋裝過 80% 就慢 10%（門檻制，不是連續遞減，所以「還能不能再拿一件」是個明確決定）。
2. **注意度**：提袋金額越高，店員視線與聽力越敏銳。這是**自動平衡**——新手拿得少就安全，高手裝滿就危險，不管玩到第幾次。
3. **被抓的代價**：現金歸零、隨機沒收兩件裝備、關卡回到第 1 次。有護身符會自動啟用保住裝備（它自己碎掉）。

### 進度不跨工作階段

現金、裝備、關卡進度**只存在記憶體裡**，關掉瀏覽器就全部歸零。每次開啟都是第 1 次下手、身上什麼都沒有。

`localStorage` 只存**犯案紀錄**（STATS）。所以：

- `最長連續沒被抓` 是**歷史最佳**，跨越所有工作階段
- `目前連續` 每次開啟重設為 0，是這次的成績
- 藏身處的「現有裝備」欄可以檢視身上有什麼，被抓後會標出沒收了哪兩件
- 標題選單的「清除犯案紀錄」是兩段式確認，唯一需要手動清的就是紀錄

### 店員 AI

顯式 FSM：`DORMANT / CAMEO / PATROL / INVESTIGATE / SEARCH / CHASE / RETURN / STUNNED`。

- Waypoint 圖**每次下手重建**（灑格子後濾掉被擋住的點，鄰接用通行性判定），所以貨架怎麼重排都會自己適應。
- 視線用角錐 + 遮蔽判定，高度取決於玩家姿勢（站 1.45m／潛行 1.05m／縮小 0.40m／跳躍時加上跳躍高度）。
- **追滿 10 秒抓不到就放棄**，走開並且有 6 秒完全不理你。沒有這個冷靜期，他一轉身又看到你，等於沒放棄。
- 第一次下手他是休眠的，只在第 33 秒客串走過遠處走道一次，讓玩家知道「店裡有別人」——之後的選擇才算風險決策。

### 每次都不一樣的東西

- **六種貨架佈局**（長排／錯位／田字／島型／環形／稀疏），隨機抽，右上角會顯示代號。
- **鐵捲門**隨機封 0–2 條橫向通道（只在南北向佈局），逃脫路線每次不同。西側走道與南側通道永遠通行，出口不會被鎖死。
- **商品位置與稀有度每次洗牌**，記路線沒有用。
- **鑰匙**隨機掉在賣場某處，可開冷凍室的保險箱，50% 出貴重品。
- **商店每次隨機四選**，可付費換一批。

### 監視螢幕

六台吊掛式螢幕共用一張即時繪製的 canvas 俯視圖（約 9fps，刻意保留頓感）。顯示牆／貨架／出口／冷凍室、玩家白點與視線方向、店員紅點。

停電後斷訊，每 1.6 秒只回來 0.4 秒——**最需要情報的時候情報最少**。

## 調參面板（按 T）

這是原型真正的產出。約 30 個參數即時生效，分三區：玩家、店員、經濟與節奏。

最常動的幾個：

| 參數 | 現值 | 說明 |
|---|---|---|
| `clerkSense` | 0.60 | 店員敏感度（視線與聽力），基礎值的倍率 |
| `clerkSpeedMul` | 0.90 | 店員速度倍率 |
| `growthPer3` | 0.02 | 每三次下手，上面兩項各加多少 |
| `chaseGiveUp` | 10 | 追多久就放棄（秒） |
| `catchDist` | 1.35 | 抓到距離。**覺得挫敗先調這個，不要動歸零規則** |
| `heatVision` | 0.45 | 注意度對視線的加成 |
| `loadThreshold` | 0.80 | 負重門檻 |
| `aimAssist` | 15 | 拿東西的瞄準寬容度（度） |
| `gearLost` | 2 | 被抓時沒收幾件裝備 |

「重置參數」會回到預設值，紀錄不受影響。

## 驗證數據

目前唯一一組完整數據（21 次下手，v1.x 期間）：

```
連續 8 次沒被抓（個人最佳 8 次）
單次最高獲利 $977
帶著非賣品脫身 6 次
最深撐到第 21 次
總共下手 21 次，被抓 8 次
```

### 結論

**核心假設成立，且是強訊號。** 一張灰盒地圖、沒有美術音樂，玩家連續玩了 21 次並反覆回頭拿非賣品 6 次。交接包最在意的兩個指標——非賣品取用率與重玩率——都過關。

### 當時暴露的兩個問題（已處理）

1. **難度曲線是反的**：8 次被抓全部集中在前 13 次，後 8 次一次都沒死。前期 62% 死亡率、後期 0%。→ 加入注意度機制（動態、跟著貪婪程度走），並把次數遞增放得很緩。
2. **經濟通膨三倍**：單次 $977 vs 設計目標 $220–350，升級階梯兩次就買完。→ 升級擴到 13 項、上限 $1500、加入一次性道具當現金出口。

### 還沒收集到的

v2.0 之後的大量改動（負重、注意度、13 項升級、一次性道具、小跳、隨機佈局、鑰匙保險箱、歸零規則）**都還沒有實測數據**。下一輪測試應該至少跑 5 次，並確認：

- 六種佈局有沒有走不通、商品浮空、店員卡住的
- 歸零規則的挫敗感是否大於刺激
- 注意度有沒有真的改變「要不要再拿一件」的決定

在藏身處按「複製戰績」可以把數字複製出來。

## 與原始交接包的偏離（依 CLAUDE.md 要求記錄）

`CLAUDE.md` 要求技術決策不得擅自變更，變更需記錄理由。以下是實際偏離：

| 偏離 | 理由 |
|---|---|
| **用 Three.js 寫網頁原型，而非 Cocos** | `CLAUDE.md` 明文禁止 DOM/HTML 遊戲——那條規則是針對**最終產品**。這是拋棄式驗證原型：核心假設的答案藏在數值與節奏裡，改一個數字重新整理就能測，在 Cocos 裡要重 build。程式碼不會轉移，商品定義、waypoint 佈局、數值全部可以。 |
| **加入跳躍** | 原文列為「除非絕對必要否則不做」。加入的理由是**情報行為**：跳起來視點從 1.65m 到 2.33m，越過 1.9m 貨架看一眼店員在哪，與監視螢幕互補。做成付費升級，且跳起時視線判定同步升高（他也看得到你）。 |
| **題材從「夜班補貨員」改為「小偷」** | 原設定是員工卻在拿商品換現金、還有「風險加成」，敘事與機制打架。竊賊的心理正是「已經可以走卻回頭」，改完之後敘事與核心迴圈對齊。 |
| **被抓後全部歸零** | 原設計只失去本局 loot，永久現金與升級保留。改成 roguelite 硬重置，讓「最長連續幾次沒被抓」成為唯一分數——這是玩家實測後主動要求的方向。 |
| **加入模組化佈局與隨機化** | `IMPLEMENTATION_PLAN.md` 把 procedural generation 列在禁止項目。這裡不是程序生成地形，是**固定外殼 + 預先手工編寫的六種貨架排列隨機抽**。外殼與地標不動，所以導引燈帶、監視器、招牌、教學腳本全部有效。 |

未偏離的部分：沒有多人、沒有 Roblox、沒有後端、沒有登入、沒有 IAP、沒有 NavMesh、沒有多怪、沒有寫實暴力。

## 已知限制

- **iOS 無法全螢幕**，只能用「加入主畫面」。Apple 的限制，程式繞不過去。
- **排行榜是本機的**。紀錄存在各自瀏覽器的 localStorage，不會上傳、不跨裝置。要真正的線上排行榜需要後端，那超出原型範圍（交接包也把 backend 列在禁止項目）。
- **貨架佈局 C/D/E 不會出現鐵捲門**，因為門會插進橫向貨架裡。
- 區域招牌（零食／飲料／日用品…）位置固定，換佈局後不一定對得上實際走道，屬已知的美觀問題。

## 難度設計方向（已定案）

目標是**魂系那種靠技術過關的成就感**，不是數值膨脹的挫敗。

決策：**保留隨機化，難度來自即時應變**，而不是背地圖後完美執行。

這個取捨要記清楚，因為它有反直覺的後果：

- 魂系的精通感通常來自**固定關卡的記憶**。這裡刻意選了相反方向，所以「重複挑戰同一張圖直到熟練」不是設計意圖，**不要因為覺得隨機很吵就把它改掉**。
- 既然玩家無法靠記憶預判，**威脅的當場可讀性就是難度公平與否的關鍵**：店員在哪、有沒有聽到你、視線朝哪，都必須看得出來。監視螢幕、被追紅框、腳步聲音量都屬於這一層，不是裝飾。
- 補技術深度時，優先加**不依賴記憶的機制**（例如衝刺體力條 —— 何時衝、何時省是即時判斷），而不是調高店員的敏感度與速度。後者容易變成「被看到就死」，那是運氣不是技術。

目前數值刻意偏寬鬆（`clerkSense` 0.60、`clerkSpeedMul` 0.90、追 10 秒放棄），等實測回饋再往上調。

## 下一步

玩家已核可但尚未實作的設計：

**四個房間漸進解鎖** — 第 5 次後啟用 2 個房間、第 10 次後 3 個、第 20 次後 4 個。貴重物只在最深的房間，出口永遠在最外面，所以**用距離換難度**，而不是調店員數值。

這是目前所有待辦中最大的一項，會動到新房間幾何、門洞、導引燈帶延伸、跨房間 waypoint、每房間監視器、店員巡邏範圍。建議先把 v2.0 之後的改動測過再開始。

之後若數據支持，才進 Cocos 的 M0/M1（見 `night_shift_claude_handoff/IMPLEMENTATION_PLAN.md`）。
